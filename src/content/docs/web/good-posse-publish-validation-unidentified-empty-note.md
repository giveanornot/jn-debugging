## 快速結論

「未命名短文，沒有文字或照片」不表示目前正在編輯的短文一定遺失內容。發布前檢查會掃描整個公開集合；任一篇空白且仍標示為公開的短文都會阻擋發布。

目前訊息只依標題／圖片推導顯示名稱。純文字、無標題、無圖片的短文會全部顯示成相同的「未命名短文」，因此診斷結果缺少定位資訊。

## 症狀

- 短文編輯器明確顯示已儲存的文字。
- 「發布整個網站」仍報：

```text
未命名短文，沒有文字或照片
```

- 發布前面板同時顯示將輸出多篇公開內容，表示檢查不是只針對目前編輯器。

## 影響範圍

- Service：靜態網站發布前的內容完整性檢查。
- 使用者影響：一則空白公開短文可阻擋整站發布，且難以從訊息定位。
- 資料風險：低；檢查阻止空白貼文進入公開 release，沒有自動刪除資料。

## 排查

確認 validator 是否處理所有 `status === "published"` 的貼文，而非只處理 active draft：

```ts
const selected = posts.filter((post) => post.status === "published");
```

再檢查每個候選的 markdown blocks、衍生 `body` 與媒體數量。短文在三者皆空時會被標為 `note-content` 問題。

若目前編輯器的文字已保存，改從其他公開短文找空白記錄，特別是建立後曾清空、或保留了先前發布快照的短文。

## 根因

發布 validator 的範圍正確地涵蓋整個公開集合，但介面將無標題短文的錯誤壓縮成通用名稱，未顯示日期、內容片段、貼文 ID 或可點擊的編輯入口。

## 修正

尚未實作介面修正。保留 validator 的阻擋行為；後續應讓每個 issue 提供可辨識的貼文資訊與「開啟這篇」動作，而不是只顯示通用名稱。

## 驗證

```bash
cd good-posse/poc
npm test
```

- 建立兩篇公開短文，其中一篇有文字、另一篇空白。
- 確認 validator 只回報空白短文。
- 介面修正後，確認錯誤列能唯一定位該篇並直接開啟編輯器。

## 下次先查

遇到空白短文錯誤時，先確認發布檢查的總篇數，再找所有公開短文；不要從目前正在編輯的那篇直接推論內容遺失。
